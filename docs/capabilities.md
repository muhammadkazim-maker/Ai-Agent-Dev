## 2. Known Limitations & Honest Boundaries
1. **Physical 20-Minute Phone Run Pending Hardware Execution**: Automated JVM and Robolectric tests verify all Phase 07 state machines, Silero VAD cough/throat-clear/typing rejection and short/quiet word acceptance, serialized audio playback, watchdogs, hardware stall detection, `GoAway` rotation, redaction, and UI diagnostics; live multi-minute physical-phone audio/thermal/network stability requires on-device execution by the operator.
2. **Unrelated Clear Human Speech Near the Microphone (Wake-Free Limitation)**: When an active foreground conversation is running in wake-free mode (without requiring `"Jarvis"`), on-device Silero VAD + acoustic burst discrimination rejects non-speech acoustics (varied/longer coughs, repeated throat-clears, typing, table taps, ambient noise), and server-side silent completions (`NO_RESPONSE_TURN_IGNORED`) return cleanly to `LISTENING`. However, a single-microphone VAD + Gemini Live native-audio pipeline without speaker enrollment or a mandatory wake word cannot reliably distinguish clear nearby human speech addressed to another person in the room from speech addressed to the assistant. Operators should use **Pause** when engaging in side conversations.
3. **Physical Audible Completion & Pronunciation Source Isolation (Device-Verification Items)**: Local playback serialization (`previousWriteJob?.join()`), `220ms` prebuffering, and the `80ms` trailing silence cushion in `AndroidStreamingAudioTrackDriver.finishStreamForDrain` operate at the software `AudioTrack` stream boundary. The `80ms` software cushion does **not** guarantee physical acoustic completion across all device HALs/speakers/Bluetooth routes, and any remaining stutter, distortion, or pronunciation anomalies cannot be attributed solely to server-side synthesis without isolating client playback/buffering vs. server audio generation during physical-device verification.
4. **Output-Start Latency Is an Estimate**: `outputStartLatencyEstimate` (`tSpeechEndMs -> tFirstHardwareWriteMs`) measures elapsed monotonic time from local end-of-speech detection to the first positive `AudioTrack.write` return. It does **not** measure physical acoustic speaker output delay across the Android audio HAL or Bluetooth/speaker hardware.
5. **Client Transport Submission vs. Server Receipt**: `tEndSubmittedMs` records when the client transport call (`sendStopActivityRealtime()`) completes locally; actual server receipt occurs over the network and is only observable when the server sends an input transcription acknowledgment (`tServerInputAckMs`) or begins its response (`tFirstResponseMs`).
6. **Explicit Half-Duplex Policy (No Spoken Barge-In)**: The microphone is intentionally disabled during `THINKING` (`PROCESSING`) and `SPEAKING` to prevent acoustic echo feedback into the live session.
7. **Zero Action Tools & No Accessibility Service**: `tools = emptyList()` (`registeredActionToolsCount = 0`), with no device action tools or AccessibilityService registered.

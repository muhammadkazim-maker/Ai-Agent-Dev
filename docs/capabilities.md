# OmniVoice Rebuild — Capabilities & Honest Limitations (`docs/capabilities.md`)

## 1. Active Capabilities in Phase 06A (`ov-rebuild-p03-20261111`)

| Capability Domain | Status in Phase 06A | Implementation Details |
| :--- | :--- | :--- |
| **Concise Authoritative System Instruction (`LiveConfigConstants.AUTHORITATIVE_SYSTEM_INSTRUCTION`)** | **ACTIVE (Unit-Tested; Real-Device Gemini Language Verification: `NOT RUN`)** | Single concise configuration-only system instruction passed to `liveModel(..., systemInstruction = content { text(systemInstruction) })` on initial connect and every reconnect. Instructs Gemini Live to evaluate every turn independently and respond unmistakably in the language of the speaker's current utterance (English, Urdu/Roman Urdu, or mixed Urdu-English), treat one-turn requests such as `'answer in English'` as applying only to that response unless `'from now on'`, `'always'`, `'ab se'`, or `'hamesha'` is spoken, never let a previous response language control the next turn, keep a calm, friendly, direct, concise personality, and never claim unverified actions. |
| **Pinned `"Kore"` Native-Audio Voice (`LiveConfigConstants.DEFAULT_NATIVE_AUDIO_VOICE`)** | **ACTIVE** | Pins `SpeechConfig(voice = Voice("Kore"))` in `FirebaseAiLiveTransportDriver.connectAndHandshake` without setting `speechConfig.languageCode`, preserving the same `"Kore"` voice across initial connect, reconnects, network restore, and Pause/Resume. |
| **Serialized Foreground Active Conversation Coordinator (`ConversationCoordinator` + `TurnRuntimeState`)** | **ACTIVE** | Coordinates `IDLE`, `PREPARING`, `LISTENING`, `THINKING` (`PROCESSING`), `SPEAKING`, `PAUSED`, `STOPPED`, and `ERROR` states in one serialized state machine using a fresh isolated `TurnRuntimeState` per turn and 11-checkpoint per-turn tracing (`TurnTraceStep`). Enforces 4-gate pre-`PROCESSING` validation, cancellable `FIRST_RESPONSE_TIMEOUT` watchdog with single bounded recovery, and deterministic `STALE_CALLBACK_DROPPED` filtering. |
| **Automatic Capture Restoration & Actual Resource Release** | **ACTIVE** | After `SPEAKING` hardware drain completes, automatically releases prior `AudioCapture` and `LiveAudioPlaybackAdapter` resources (`resourceReleaseBeforeCaptureCount`) and restores `PREPARING -> LISTENING` for the next turn while active conversation mode is enabled. Verified across 20 continuous turns with zero leaked jobs, timers, watchdogs, tracks, or captures (`resourceSnapshot()`). |
| **Inactivity-Based Session Closure with Visible Setting** | **ACTIVE** | Visible `InactivityTimeoutOption` selector (`30s`, `1m`, `2m`, `5m`) on the main Command Deck and in Settings. Resets on speech frames and cleanly closes idle `LISTENING` sessions to `IDLE` (`INACTIVITY_SESSION_CLOSED`) when the timeout expires. |
| **Remembered Auto-Resume on Screen Reopen (Never Overrides Pause/Stop)** | **ACTIVE** | After first-use consent and configuration (`hasCompletedFirstUseConsentAndConfig` + `RECORD_AUDIO` granted), reopening the visible conversation screen may auto-resume according to `autoResumeOnScreenReopen`. Strictly blocked (`autoResumeBlockedByPauseOrStopCount`) whenever the operator deliberately paused or stopped. |
| **Large Pause / Resume & Stop Controls & Explicit Half-Duplex Policy** | **ACTIVE** | 64dp+ **Pause**, **Resume**, and **Stop** buttons with strict precedence (`STOP > PAUSE > RESUME > START`). Explicitly displays `HALF-DUPLEX EXPLICIT (Mic disabled during THINKING & SPEAKING; spoken barge-in not claimed)` (`isSpokenBargeInClaimed = false`). |
| **Bounded Session Dialogue & Orientation Preservation** | **ACTIVE** | Bounds `sessionDialogueHistory` to `8` turns and `transcript` to `24` entries. Preserves the single ViewModel-scoped `ConversationCoordinator` across orientation changes (`onConfigurationChangePreserved`) without duplicating coordinators or dropping active turns. |
| **Complete Native-Audio Playback (`LiveAudioPlaybackAdapter`)** | **ACTIVE** | Uses a ~200ms `AudioTrack.MODE_STREAM` buffer on `Dispatchers.IO`, verifies `STATE_INITIALIZED` and `PLAYSTATE_PLAYING`, verifies PCM MIME/sample rate, loops over partial/zero writes without dropping bytes, inspects real negative write errors with at most one clean track recreation, separates `framesReceivedFromServer` vs `totalFramesWrittenToHardware` vs `hardwarePlaybackHeadFrames` (with 32-bit wraparound handling), keeps the track in `PLAYSTATE_PLAYING` until hardware drain reaches accepted frames before releasing, and never reuses a released `AudioTrack`. |
| **Single-Flight LiveSession Ownership, Explicit Turn Signals & Close Classification (`GeminiLiveConnectionAdapter`)** | **ACTIVE** | Single authoritative `LiveSession` owner guarded by `connectMutex` + `inFlightConnectDeferred` (`DISCONNECTED -> CONNECTING -> SETUP_ACCEPTED -> ACTIVE -> RECONNECTING/FAILED`). Configures `ActivityDetectionConfig.disabled()` with explicit `sendStartActivityRealtime()` once per spoken turn and single `sendStopActivityRealtime()` on end-of-turn. |
| **Connectivity Monitoring & Offline Gate (`LiveNetworkMonitor`)** | **ACTIVE** | Verifies `NET_CAPABILITY_INTERNET` and `NET_CAPABILITY_VALIDATED` before every handshake and voice turn without initial callback flicker. Invalidates active sessions to `NETWORK_UNAVAILABLE` on internet loss. |
| **Firebase App Check Debug & Production Play Integrity** | **ACTIVE** | `configureAppCheck(this, intent)` runs in `MainActivity.onCreate()` before `Firebase.ai` access. Debug builds install `DebugAppCheckProviderFactory.getInstance()`; release builds install `PlayIntegrityAppCheckProviderFactory.getInstance()`. |

## 2. Known Limitations & Honest Boundaries (Phase 06A)
1. **No Voice Selector UI in Phase 06A**: Voice selection UI is intentionally excluded from Phase 06A stabilization; the native-audio voice is pinned to `"Kore"`.
2. **Real-Device Gemini Spoken Language Verification (`NOT RUN`)**: Unit tests verify that the pinned `"Kore"` voice and exact concise `AUTHORITATIVE_SYSTEM_INSTRUCTION` are passed to the Live session and that no local `LanguagePolicyClassifier` or per-turn language persistence exists, but unit tests do **not** prove the real Gemini provider's spoken language behavior. Real-device Gemini language verification is `NOT RUN` until the 8-step physical-phone checklist is executed.
3. **Explicit Half-Duplex Policy (No Spoken Barge-In)**: The microphone is intentionally disabled during `THINKING` (`PROCESSING`) and `SPEAKING` to prevent acoustic echo feedback into the live session.
4. **Zero Action Tools & No Accessibility Service**: `tools = emptyList()` (`registeredActionToolsCount = 0`), with no device action tools or AccessibilityService registered.
